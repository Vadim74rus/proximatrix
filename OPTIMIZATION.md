# Оптимизации: стабильность, отказоустойчивость, производительность

## Обзор изменений

### 1. Главный процесс (index.js)

- **Graceful shutdown**: при SIGINT/SIGTERM — корректная остановка с таймаутом 15 с.
- **unhandledRejection**: логирование необработанных отклонений промисов.
- **Уведомления**: отправка в Telegram не блокирует основной поток (fire-and-forget с логированием ошибок).

### 2. MongoDB (db.js)

- **Пул соединений**: `maxPoolSize: 20`, `minPoolSize: 2`.
- **Таймауты**: `serverSelectionTimeoutMS: 10000`, `connectTimeoutMS: 10000`.
- **Простой**: `maxIdleTimeMS: 60000`.

### 3. Кэш секретов (users-mongo.js)

- **refreshSecretsCache**: при ошибке MongoDB старый кэш не сбрасывается, ошибка логируется.
- **invalidateCache**: при ошибке обновления кэш не теряется.

### 4. Connection tracker (connection-tracker.js)

- **registerConnection**: обёрнут в try/catch; при ошибке отключения пользователя возвращается «Internal error».
- **logConnection**: вызов без await (fire-and-forget), чтобы не блокировать приём подключений.
- **unregisterConnection**: синхронный, без ожидания записи в БД.

### 5. MTProto (mtproto-server.js)

- **Исправление**: проверка «нет секретов» использует `this.getSecrets` вместо несуществующего `this.options.getSecrets`.
- **Нормализация IP**: `::ffff:1.2.3.4` приводится к `1.2.3.4` для единообразного учёта.

### 6. HTTP/HTTPS прокси (http-proxy-server.js)

- **Таймаут запроса**: `PROXY_REQUEST_TIMEOUT` (по умолчанию 60 с), задаётся через `process.env.PROXY_REQUEST_TIMEOUT`.
- **Таймаут сокета CONNECT**: `PROXY_SOCKET_TIMEOUT` (по умолчанию 120 с).
- **Логи CONNECT**: отключаются через `PROXY_LOG_CONNECT=0` (меньше I/O при большой нагрузке).
- **Обработка ошибок**: закрытие сокетов в try/catch, чтобы избежать повторных ошибок.

### 7. Admin API (admin-api.js)

- **Лимит тела запроса**: 256 KB (`MAX_BODY_SIZE`), защита от переполнения памяти и DoS.
- **Ответ 413**: при превышении лимита тела.
- **Таймауты сервера**: `keepAliveTimeout: 65000`, `headersTimeout: 66000` (рекомендации Node.js для балансировщиков).

### 8. Уведомления (notify-service.js)

- **Таймаут запроса**: 10 с, по истечении — `req.destroy()`, ответ «Timeout».
- **Меньше логов**: при отключённых уведомлениях сообщение «уведомления отключены» не пишется при каждом событии.
- **Путь API**: корректное формирование path для любого `NOTIFY_API_URL`.

---

## Переменные окружения (опционально)

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `PROXY_LOG_CONNECT` | (включено) | `0` — отключить логи CONNECT для HTTP(S) прокси |
| `PROXY_REQUEST_TIMEOUT` | 60000 | Таймаут HTTP-прокси запроса, мс |
| `PROXY_SOCKET_TIMEOUT` | 120000 | Таймаут сокета CONNECT, мс |

---

## Рекомендации

1. В продакшене при высокой нагрузке можно выставить `PROXY_LOG_CONNECT=0`.
2. При нестабильной сети можно увеличить таймауты MongoDB в `db.js`.
3. При необходимости увеличить лимит тела API — изменить `MAX_BODY_SIZE` в `admin-api.js`.
