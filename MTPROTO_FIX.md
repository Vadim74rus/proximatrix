# MTProto прокси «недоступен» — что проверить

## Почему ссылка не открывается

MTProto **не использует HTTPS** — это обычный TCP на выбранном порту. Ссылка `https://t.me/proxy?server=...` только открывает настройки в Telegram, само подключение идёт по TCP.

Чаще всего мешает одно из двух:

1. **Порт 443 занят** (nginx, Apache, другой контейнер) — тогда MTProto не слушает 443 и Telegram не может подключиться.
2. **Порт закрыт файрволом** на сервере или у хостера.

---

## Решение: использовать порт 8444

В проекте MTProto по умолчанию переведён на **порт 8444**, чтобы не пересекаться с веб-сервером на 443.

### На сервере выполните

```bash
cd /opt/proximatrix
git pull
```

Проверьте, что в `config.json` у MTProto указано:
- `"port": 8444`
- `"publicIp": "77.221.156.12"`

В `docker-compose.yml` должно быть:
- `"8444:8444"` (и больше не должно быть проброса 443 в контейнер).

Откройте порт и перезапустите:

```bash
ufw allow 8444/tcp
ufw status

docker compose down
docker compose up -d --build
docker compose logs proximatrix
```

В логах должна быть ссылка вида:
```text
https://t.me/proxy?server=77.221.156.12&port=8444&secret=XXXXXXXX
```

Эту ссылку вставьте в Telegram (Настройки → Данные и хранилище → Прокси → Добавить прокси → вставить ссылку).

## Если всё ещё недоступен

### 1. Проверить, слушает ли контейнер порт

**На сервере:**

```bash
docker compose ps
ss -tulpn | grep 8444
# или
netstat -tulpn | grep 8444
```

Должен быть процесс (docker-proxy или node), слушающий 8444.

### 2. Проверить файрвол

```bash
ufw status | grep 8444
# Должно быть: 8444/tcp ALLOW
```

Если правила нет:
```bash
ufw allow 8444/tcp
ufw reload
```

### 3. Проверить с другого компьютера

С вашего ПК (PowerShell или командная строка):

```bash
telnet 77.221.156.12 8444
```

Или в PowerShell:
```powershell
Test-NetConnection -ComputerName 77.221.156.12 -Port 8444
```

Если подключение есть — порт открыт, проблема может быть в блокировке у провайдера/в стране. Если нет — порт закрыт или сервис не слушает.

### 4. Ввести данные вручную в Telegram

В Telegram: **Настройки** → **Данные и хранилище** → **Прокси** → **Добавить прокси** → **MTProto**:

- **Сервер:** `77.221.156.12`
- **Порт:** `8444`
- **Секрет:** скопировать из логов (строка `Secret: ...`)

## Если хотите снова использовать порт 443

Убедитесь, что **ничто** не слушает 443 на хосте:

```bash
ss -tulpn | grep 443
```

Если 443 свободен, в `config.json` можно поставить `"port": 443`, в `docker-compose.yml` — `"443:443"`, открыть `ufw allow 443/tcp` и перезапустить контейнеры. Тогда в ссылке будет `port=443`.

## Скрипт диагностики на сервере

На сервере выполните:

```bash
cd /opt/proximatrix
bash check-mtproxy.sh
```

Скрипт покажет: порт в конфиге, слушает ли 8444, открыт ли UFW, доступен ли порт с localhost.

---

## Хостинг: отдельный файрвол в панели

У многих VPS (например, Selectel, Timeweb, REG.RU и др.) кроме UFW есть **файрвол в панели управления**. Нужно открыть там **входящий TCP-порт 8444** для IP сервера или для всех (0.0.0.0/0). Иначе с интернета порт будет закрыт, даже если UFW разрешает.

Зайдите в панель хостинга → Сеть / Firewall / Брандмауэр → добавьте правило: **разрешить входящий TCP 8444**.

---

## Проверка порта из интернета

- **С вашего ПК (PowerShell):**  
  `Test-NetConnection -ComputerName 77.221.156.12 -Port 8444`  
  Смотрите строку `TcpTestSucceeded: True` — порт открыт.

- **Онлайн-проверка:**  
  [yougetsignal.com/open-port-checker](https://www.yougetsignal.com/tools/open-ports/) — укажите IP `77.221.156.12`, порт `8444`, нажмите Check. Если порт открыт — проблема может быть в блокировке Telegram у провайдера или в коде прокси.

---

Итог: после перехода на порт **8444**, открытия его в UFW **и в панели хостинга** и перезапуска контейнеров используйте в Telegram ссылку с **port=8444** (или введите сервер/порт/секрет вручную).
