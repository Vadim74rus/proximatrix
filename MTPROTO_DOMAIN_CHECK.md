# Проверка подключения по домену

Если ссылка **с IP** работает:
`https://t.me/proxy?server=77.221.156.12&port=8444&secret=...`

А ссылка **с доменом** не подключается:
`https://t.me/proxy?server=ваш-домен.ru&port=8444&secret=...`

то Telegram при подключении не может достучаться до сервера по имени домена. Обычно это из‑за DNS.

---

## Что проверить

### 1. Резолвится ли домен в нужный IP

**На своём компьютере (PowerShell или cmd):**
```cmd
nslookup ваш-домен.ru
```
В ответе должна быть строка с адресом **77.221.156.12**.

**На сервере (SSH):**
```bash
nslookup ваш-домен.ru
# или
dig +short ваш-домен.ru
```
Ожидается: `77.221.156.12`.

Если видите другой IP или ошибку — проблема в DNS.

### 2. Настройки DNS в Рег.ру

**DNS-серверы (ns1.reg.ru, ns2.reg.ru) менять не нужно** — это серверы, на которых хранятся записи вашего домена. Их меняют только при переносе домена к другому регистратору.

Важно проверить **ресурсные записи** (A, при необходимости AAAA):

1. Зайдите в панель Рег.ру → домен **ваш-домен.ru** → раздел «ДНС-серверы и зона» / «Управление зоной» / «Ресурсные записи».
2. Должны быть **A-записи**:

| Имя (хост) | Тип | Значение      | TTL (по желанию) |
|------------|-----|---------------|------------------|
| @          | A   | 77.221.156.12 | 300–3600         |
| www        | A   | 77.221.156.12 | 300–3600         |

- **@** — это корневой домен (ваш-домен.ru).
- Если записи не было — добавьте, сохраните. Подождите 5–30 минут (распространение DNS).

3. **AAAA (IPv6):** если есть запись AAAA для @ или www — либо удалите её, либо укажите корректный IPv6 вашего сервера. Иначе клиент может пытаться подключиться по IPv6 и не доходить до 77.221.156.12.

### 3. Доступность порта по домену

С вашего ПК (если есть curl):
```bash
curl -v --connect-timeout 5 telnet://ваш-домен.ru:8444
```
или с сервера:
```bash
nc -zv ваш-домен.ru 8444
```
Должно быть «Connection established» или «succeeded». Если «Connection refused» или таймаут — либо DNS указывает не на ваш сервер, либо порт 8444 закрыт/заблокирован.

---

## Если DNS в порядке, но по домену всё равно не подключается

- Разные сети (мобильный интернет, другой провайдер) могут кэшировать старый DNS или использовать другие серверы — попробуйте с другого телефона/сети.
- Временно можно оставить в конфиге **IP** для генерации ссылок (все будут подключаться по 77.221.156.12), а домен использовать только когда резолв будет стабильно давать 77.221.156.12.

---

## Запасная ссылка с IP из API

В конфиге задан **serverIp** (реальный IP сервера). Тогда API отдаёт две ссылки:

- **link** — с доменом или publicIp: `https://t.me/proxy?server=77.221.156.12&port=8444&secret=...`
- **linkIp** — с IP: `https://t.me/proxy?server=77.221.156.12&port=8444&secret=...`

Если по домену не подключается, выдавайте пользователю **linkIp** (она всегда должна работать при открытом порте 8444).

В **config.json**: `"serverIp": "77.221.156.12"`.  
В **Docker**: `PROXY_SERVER_IP: "77.221.156.12"`.

---

## Полный переход на ссылки с IP

Чтобы везде генерировать только ссылки с IP:

- **config.json:** задайте `"publicIp": "77.221.156.12"` (и при желании уберите `serverIp`).
- **Docker:** задайте `PROXY_PUBLIC_IP: "77.221.156.12"`.

Перезапустите контейнеры. После исправления DNS можно снова указать домен в `publicIp`.
