# Отслеживание IP и контроль доступа

Система автоматически отслеживает IP-адреса подключений и контролирует использование MTProto секретов.

---

## Как это работает

### 1. Первое подключение

При первом подключении пользователя:
- IP-адрес автоматически добавляется в список разрешенных (`allowedIPs`)
- Подключение разрешается
- Событие логируется в `connectionHistory`

### 2. Обнаружение подозрительной активности

Если один секрет используется **одновременно** с разных IP-адресов (сколько угодно человек с разных IP):
- **Все подключения разрешаются** — никто не отключается и не блокируется
- **Отправляется уведомление администратору в Telegram** (если настроено `NOTIFY_API_URL` и `NOTIFY_SECRET`) с данными аккаунта
- В логах выводится предупреждение
- Событие логируется в `connectionHistory` со статусом `suspicious`

Решение принимает администратор: просмотреть историю (`GET /api/users/{id}/connections`) и при необходимости отключить пользователя: `POST /api/users/{id}/disable`

### 3. Действия администратора

1. **Просмотреть историю подключений:**
   ```bash
   curl -H "X-API-Key: ваш-ключ" \
     http://77.221.156.12:9090/api/users/{id}/connections
   ```

2. **Отключить пользователя** (если принято решение):
   ```bash
   curl -X POST -H "X-API-Key: ваш-ключ" \
     http://77.221.156.12:9090/api/users/{id}/disable
   ```

3. **Включить пользователя обратно** (если отключили по ошибке):
   ```bash
   curl -X POST -H "X-API-Key: ваш-ключ" \
     http://77.221.156.12:9090/api/users/{id}/enable
   ```

4. **Сбросить разрешенные IP** (опционально):
   ```bash
   curl -X POST -H "X-API-Key: ваш-ключ" \
     http://77.221.156.12:9090/api/users/{id}/reset-ips
   ```

## Структура данных в MongoDB

### Поля пользователя

- `allowedIPs` — массив разрешенных IP-адресов (автоматически заполняется)
- `connectionHistory` — история подключений (последние 100 записей)
- `lastConnectionIP` — последний IP подключения
- `lastConnectionTime` — время последнего подключения

### Формат записи в connectionHistory

```json
{
  "ip": "192.168.1.100",
  "status": "connected",  // или "disconnected", "suspicious", "blocked"
  "reason": null,  // или описание причины блокировки
  "timestamp": "2025-02-11T12:30:00.000Z",
  "telegramId": "123456789",  // Telegram ID владельца секрета
  "firstname": "Иван",  // имя владельца секрета
  "username": "ivan"  // username владельца секрета
}
```

**Важно:** В истории подключений отображаются данные **владельца секрета** из базы данных. Если секрет используется с разных IP, для всех IP будут показаны данные владельца. MTProto прокси не передает информацию о реальном подключившемся пользователе.

## Примеры использования

### Просмотр истории подключений

```bash
# Получить последние 50 подключений
curl -H "X-API-Key: proximatrix-api-key-change-in-production" \
  http://77.221.156.12:9090/api/users/65a1b2c3d4e5f6789012345/connections

# Получить последние 10 подключений
curl -H "X-API-Key: proximatrix-api-key-change-in-production" \
  "http://77.221.156.12:9090/api/users/65a1b2c3d4e5f6789012345/connections?limit=10"
```

### Восстановление доступа после блокировки

```bash
# 1. Проверить историю
curl -H "X-API-Key: ваш-ключ" \
  http://77.221.156.12:9090/api/users/{id}/connections

# 2. Включить пользователя
curl -X POST -H "X-API-Key: ваш-ключ" \
  http://77.221.156.12:9090/api/users/{id}/enable

# 3. Сбросить IP (если нужно разрешить новый IP)
curl -X POST -H "X-API-Key: ваш-ключ" \
  http://77.221.156.12:9090/api/users/{id}/reset-ips
```

## Важные замечания

1. **Одновременные подключения**: Система отслеживает только одновременные подключения. Если пользователь подключается с разных IP в разное время (не одновременно), это не блокируется.

2. **Автоматическое отключение**: Пользователь не удаляется, только отключается (`enabled: false`). Все данные сохраняются.

3. **История подключений**: Хранится последние 100 записей. Старые записи автоматически удаляются.

4. **Производительность**: Отслеживание выполняется в памяти и не влияет на производительность прокси.

## Настройка уведомлений в Telegram

Для получения уведомлений в Telegram при обнаружении подозрительной активности:

1. **Добавьте переменные в `docker-compose.yml`:**
   ```yaml
   environment:
     NOTIFY_API_URL: "https://blacknetiv.ru"
     NOTIFY_SECRET: "ваш-секретный-ключ"
   ```

2. **Или через `.env` файл** (если используете):
   ```env
   NOTIFY_API_URL=https://blacknetiv.ru
   NOTIFY_SECRET=ваш-секретный-ключ
   ```

3. **Перезапустите контейнер:**
   ```bash
   docker compose restart proximatrix
   ```

После настройки при обнаружении подозрительной активности уведомление автоматически отправится администратору в Telegram через внешний API.

**Сгенерировать секретный ключ:**
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Мониторинг

Для мониторинга подозрительной активности проверяйте логи контейнера:

```bash
docker compose logs -f proximatrix | grep "ПОДОЗРИТЕЛЬНАЯ"
```

Или просматривайте историю подключений через API для всех пользователей.
