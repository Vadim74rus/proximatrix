# Почему не подключается к прокси (t.me/proxy?server=...)

Если ссылки вида  
`https://t.me/proxy?server=77.221.156.12&port=8444&secret=...`  
**не подключаются**, проверьте по шагам ниже.

---

## 1. Секрет должен быть в базе и включён

В режиме мультипользователя (MongoDB) прокси принимает **только те секреты**, которые:

- есть в коллекции пользователей (MongoDB);
- у пользователя `enabled: true`;
- срок действия не истёк (`expiresAt` пусто или в будущем);
- секрет в формате 32 hex-символа.

Если секрет из ссылки **ни разу не добавлялся** через API (или пользователь отключён/удалён), подключение будет отклоняться.

**Что сделать:**

- Проверить список пользователей и секретов:
  ```bash
  curl -s -H "X-API-Key: ВАШ_API_KEY" "http://77.221.156.12:9090/api/users"
  ```
  или через ваш бот/админку. Убедиться, что нужный секрет есть у какого-то пользователя и он включён.

- Добавить пользователя с **нужным** секретом (если его ещё нет):
  ```bash
  curl -s -X POST -H "Content-Type: application/json" -H "X-API-Key: ВАШ_API_KEY" \
    -d "{\"secret\":\"418868b665c15491de09ba904882a58e\",\"enabled\":true}" \
    "http://77.221.156.12:9090/api/users"
  ```
  Аналогично для `e7cd7110a9cf813b107f3cd06239c84d` — у какого-то пользователя в базе должно быть поле `secret` с этим значением и `enabled: true`.

- Включить пользователя, если он был выключен:
  ```bash
  curl -s -X PATCH -H "Content-Type: application/json" -H "X-API-Key: ВАШ_API_KEY" \
    -d "{\"enabled\":true}" \
    "http://77.221.156.12:9090/api/users/USER_ID"
  ```

После изменений в базе кэш секретов обновляется автоматически; перезапуск контейнера не обязателен (но можно перезапустить для уверенности).

---

## 2. Порт 8444 открыт и слушается

На сервере:

```bash
# Слушается ли 8444
ss -tlnp | grep 8444
# или
netstat -tlnp | grep 8444
```

Должен быть процесс (node/docker) на `0.0.0.0:8444` или `:::8444`.

Файрвол (UFW):

```bash
sudo ufw status | grep 8444
# Если нет:
sudo ufw allow 8444/tcp
sudo ufw reload
```

На хостинге (панель VPS) тоже не должно быть блокировки входящего 8444.

---

## 3. Контейнер/процесс запущен

```bash
docker compose ps
docker compose logs -f proximatrix
```

В логах при старте должно быть что-то вроде:  
`MTProto прокси запущен на порту 8444`, `активных секретов: N` (N ≥ 1).

Если видите:  
`активных секретов: 0` или `нет активных секретов` — значит, в базе нет подходящих пользователей (см. п. 1).

---

## 4. Сообщения в логах при попытке подключения

При неудачном подключении в логах могут появиться:

- **«секрет не совпал с активными»** — этот секрет не найден среди включённых пользователей в MongoDB. Добавьте пользователя с этим секретом через API или включите существующего.
- **«в базе нет активных секретов»** — нет ни одного пользователя с включённым и не истёкшим секретом. Создайте пользователя через API.
- **«Подключение отклонено для секрета ... с IP»** — сработал контроль доступа (одновременное использование с другого IP и т.п.). Решение — через API (например, сброс разрешённых IP или включение пользователя).

По ним можно точнее понять причину.

---

## 5. Краткий чеклист

| Проверка | Действие |
|----------|----------|
| Секрет в базе? | `GET /api/users` — есть ли пользователь с нужным `secret`, `enabled: true` |
| Добавить секрет | `POST /api/users` с `{"secret":"32_hex_symbols","enabled":true}` |
| Порт 8444 | `ss -tlnp \| grep 8444`, `ufw allow 8444/tcp` |
| Контейнер | `docker compose ps`, логи — «активных секретов: 1+» |

Чаще всего проблема в том, что **секрет из ссылки не добавлен в базу или пользователь выключен**. Добавьте/включите пользователя с нужным секретом через API и повторите попытку подключения в Telegram.
