## 🐳 ШАГ 3: Установка Docker

**🖥️ НА СЕРВЕРЕ** (в окне PuTTY):

### 3.1. Удаление старых версий Docker (если есть)

Выполните команду:
```bash
apt remove -y docker docker-engine docker.io containerd runc
```

### 3.2. Установка Docker

Выполните команды **по очереди**, дожидаясь завершения каждой:

**Команда 1:**
```bash
apt install -y ca-certificates curl gnupg lsb-release
```

**Команда 2:**
```bash
install -m 0755 -d /etc/apt/keyrings
```
⚠️ **Важно:** Это команда `install` (без `apt`), а не `apt install`!

✅ **Если команда выполнилась без ошибок и вернула приглашение командной строки** - это нормально! Команда `install` не выводит сообщений при успешном выполнении. Это означает, что директория создана успешно.

**Проверка (опционально):**
```bash
ls -la /etc/apt/keyrings
```
Должна отобразиться пустая директория (это нормально).

**Команда 3:**
```bash
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```

**Команда 4:**
```bash
chmod a+r /etc/apt/keyrings/docker.gpg
```

**Команда 5:**
```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
```

**Команда 6:**
```bash
apt update
```

**Команда 7:**
```bash
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Это займет несколько минут. Дождитесь завершения установки.

### 3.3. Проверка установки Docker

**Проверка версии Docker:**
```bash
docker --version
```
Должна отобразиться версия (например: `Docker version 24.x.x`)

**Проверка версии Docker Compose:**
```bash
docker compose version
```
Должна отобразиться версия Docker Compose.

**Тестовый запуск:**
```bash
docker run hello-world
```

Если видите сообщение "Hello from Docker!", установка прошла успешно! ✅

## 🔍 Решение проблем

**🖥️ НА СЕРВЕРЕ** (в окне PuTTY):

### Контейнер не запускается

**Проверьте логи:**
```bash
docker compose logs proximatrix
```

**Проверьте статус:**
```bash
docker compose ps -a
```

**Проверьте, не заняты ли порты:**
```bash
netstat -tulpn | grep -E '1080|8080|8443'
```

### Прокси не работает

1. **Проверьте файрвол:**
   ```bash
   ufw status
   ```
   Порты 1080, 8080, 8443 должны быть открыты.

2. **Проверьте, что контейнер запущен:**
   ```bash
   docker ps
   ```
   Контейнер `proximatrix-proxy` должен быть в списке со статусом `Up`.

3. **Проверьте логи:**
   ```bash
   docker compose logs proximatrix
   ```

4. **Проверьте порты изнутри контейнера:**
   ```bash
   docker exec -it proximatrix-proxy netstat -tulpn
   ```
